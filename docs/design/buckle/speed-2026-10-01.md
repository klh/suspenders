## 0. The acceptance number

**Router-added latency per request, excluding upstream model time: p50
< 5 ms, p95 < 15 ms.**

Measured as `T_first_byte_to_client − T_handler_entry` (streaming) and
`T_last_byte − T_handler_entry` (non-streaming), over the micro-bench
harness in §5. Cold-connect events (TLS handshake to a cloud, DNS miss) are
counted and histogrammed separately — never silently mixed into the gate
distribution. The warm-rate is its own gate: ≥ 99% of requests must be
served on an already-established connection.

Warm-path budget allocation:

| Step                    | Budget | Mechanism                                |
| ----------------------- | ------ | ---------------------------------------- |
| bearer-key lookup       | <0.1ms | hashed key → in-memory Map               |
| policy route decision   | <0.5ms | in-memory policy pointer + latency table |
| budget/rpm/tpm check    | <0.1ms | O(1) integer counters (§3)               |
| adapter (pass-through)  | ~0     | zero transform, same dialect             |
| adapter (cross-dialect) | <1ms   | one transform, one JSON round trip       |
| upstream connect (warm) | <1ms   | pooled keep-alive socket reuse           |
| SSE pipe setup          | <0.5ms | ReadableStream pipe, no buffering        |

Warm sum ≈ 2–3 ms worst case — headroom under p50 5 ms; p95 15 ms absorbs
GC pauses, a pre-first-byte ladder hop (§5 scenario 4), and timer jitter.

## 1. What Bun gives for free (the W129 Rust-bridge counterfactual)

W129's surprise finding: LiteLLM ships a compiled Rust bridge
(`litellm/rust_bridge/`, an abi3 `.so` plus ~1.5k LOC of Python wrapper) to
accelerate hot-path dispatch — hook dispatch, chat_completions, messages,
token_counter, timeouts. A compiled escape hatch from its own Python call
stack. Buckle's structural advantage: the equivalents are already native
below the JS.

- **fetch = pooled keep-alive transport.** Bun's fetch reuses connections
  per origin automatically (no Node-style Agent construction), holds a
  64-slot idle pool per origin, and pipelines. That replaces LiteLLM's
  `custom_httpx` layer (17.5k LOC) with runtime behavior, for our two
  dialects.
- **Bun.serve = the proxy shell.** FastAPI + Starlette + uvicorn (W129
  layer 1; 19.6k LOC in proxy_server.py alone) collapses to one handler in
  one process.
- **JSON + SSE on a JIT runtime.** The Rust bridge exists because Python
  needs help; Bun's hot path is already compiled C++ under JIT'd JS. What
  remains is not escaping the runtime but not feeding it work: §2's sniff
  and allocation discipline.
- **Explicitly not free** (verified against Bun 1.4.2, the local runtime):
  HTTP/2 client support in fetch is experimental; Bun.serve HTTP/2 is
  experimental behind `{http2: true}` (ALPN over TLS); h2c is not
  dependable. Design base = HTTP/1.1 + keep-alive. HTTP/2 is a
  flag-gated, shadow-measured option — never a dependency (§6).
- **Also not free:** per-request JSON.parse of megabyte prompts, and regex
  work. belt's router-shim.ts complexity scoring runs ~6 regexes plus
  lowercase + split per request — sub-ms but real. Belt keeps that scoring;
  buckle must not duplicate it per request: score once, cache on the
  request context, never re-derive.

## 2. Transport speed

### Connections

- One implicit Bun pool per upstream origin. Fleet concurrency is ≤ ~6
  fan-outs (lesson.fanout-rate-budget), so the 64-slot idle pool is never
  contended; keep-alive means a warm request pays zero connect and zero
  TLS.
- **Pre-warm at boot and on reload.** Startup model discovery already GETs
  `/v1/models` on every upstream (the gateway-config.ts precedent). Buckle
  keeps that and treats it as warm-up: TLS + auth established before the
  first real request. A request observing a cold connect emits a
  `pool_refill` counter event (feeds the warm-rate gate). No speculative
  re-warm loop until shadow data says otherwise.
- **Local MLX upstreams (:8901–:8906, :4000):** loopback, no TLS — connect
  ≈ 0; keep-alive only avoids port churn.
- **HTTP/2 to clouds:** optional, flag-gated, measured in shadow (§1, §6).
  Not on the acceptance path.

### Zero-copy SSE tee (byte-identity is a requirement)

- The upstream response body is piped to the client **verbatim** — the
  router never re-parses or re-serializes a streaming body. Byte-identity
  is tested, not assumed: sha256 over the concatenated upstream bytes must
  equal sha256 over the concatenated client bytes, per bench run (§5).
- **Usage sniff, terminal-chunk-only.** The tee branch runs byte-prefix
  tests only and JSON.parses at most two lines per stream:
  - Anthropic dialect: `message_start` (input + cache_read +
    cache_creation tokens — the first data event) and the terminal
    `message_delta` (cumulative output tokens).
  - OpenAI dialect: buckle injects `stream_options: {include_usage: true}`
    toward the upstream, so usage is guaranteed in the final chunk. Absent
    (an MLX server ignoring it) = honest unknown in the ledger, never
    estimated (W131 doctrine).
  - Every other line is skipped by prefix match without decoding; a
    candidate line over a small size cap is ignored (usage lines are bytes,
    not kilobytes). The router never scans the stream for anything else.
- **Constant memory per stream.** A rolling ~4 KB tail window reassembles
  candidate lines — O(4 KB), not O(chunk). A slow client never stalls
  accounting: the sniff branch consumes eagerly, discards what it does not
  need, and holds no queue.
- **Request-scoped allocations minimized.** Pass-through adapters allocate
  nothing beyond the fetch itself; cross-dialect allocates one transformed
  body. Header objects, tier tables, and regexes are module-level
  constants. One AbortController per request, armed on client disconnect,
  freed with the stream.

## 3. Control-plane speed

### Hot policy reload

- fs.watch (FSEvents on macOS) on the resolved policy path — W124
  resolution order unchanged: `BELT_POLICY` env → the runtime copy at
  `~/.claude/local-llm/routing-policy.yaml` → the committed default. Zero
  request-path cost; no stat loop.
- On change: debounce ~250 ms, parse + validate off the request path, then
  an **atomic pointer swap** of the module-level policy object. In-flight
  requests finish on the old policy; readers never lock (single-threaded
  JS makes the swap safe by construction). A failed parse keeps the old
  policy and raises a board-visible counter — never a crash, never a
  restart.
- This retires the LiteLLM activation dance (regenerate config + `launchctl
kickstart -k`, which drops in-flight streams — the between-fan-outs
  discipline exists because of that). The discipline stays the rule until
  the hot swap ships; it retires with the kickstart, as W131 scheduled.

### O(1) budget counters, async ledger flush

- rpm: a ring of per-second integer counters; tpm: rolling per-minute sums;
  budget: one integer per key/team, decremented when usage arrives. A check
  is a few field loads plus a compare — no allocation, no scan, no I/O in
  the check.
- Usage rows and decrements accumulate in a bounded ring; **one async
  flush** every 5 s or 256 rows (whichever first) writes them in a single
  transaction. Crash window = up to 5 s of usage rows — an honest trade:
  budgets are a degradation guard (a runaway key degrades, not the fleet),
  not billing.
- **W92 store-binding decision.** `HttpGovernorStore.rpc()` is
  `Bun.spawnSync(["curl", ...])` per statement (hooks/lib/govdb.ts, the rpc
  method) — a process spawn + curl + JSON round trip per call, serialized.
  Sync-by-design suits the CLIs' program shape; it is wrong for a long-lived
  router in the request path. Buckle's store calls go over **native async
  fetch** to the same `/rpc` endpoint (loopback keep-alive, sub-ms) and
  only from the flusher — never curl, never inline. If flusher p99 ever
  exceeds ~50 ms under load, the answer is larger batches, not sync I/O.

### Cooldown ejection without global locks

- Per-upstream state is two plain fields: `consecFails`, `cooldownUntil`.
  Check-then-act happens inside one synchronous block between awaits —
  single-threaded JS is the atomicity. No locks, no atomics, no
  cross-upstream contention by construction.
- Ejection: `allowed_fails` consecutive failures set `cooldownUntil = now +
cooldown_time` (W124 values: 3 fails, 30 s). The route read is two field
  loads and a `Date.now()` compare. Recovery is passive window expiry plus
  a half-open probe on the next real request — the W124 semantics LiteLLM
  gave us, minus the Redis DualCache. Single-node is the honest scale; the
  store seam is the escape hatch if that ever changes.

## 4. Model-side aids buckle exposes as routing metadata

Buckle does not execute model-side speedups — it carries them as metadata
on the upstream inventory so belt's scoring can prefer them. Absent flag =
absent capability, honest omission (servicemon doctrine: omit the family,
never fake zeros).

- **spec_decode (MTP / draft) — 30B+ MLX residents only.** W115 evidence:
  the magnitude engine ran MTP speculative decoding on a 4B (5 proposed /
  5 accepted) and rapid-mlx **without** any spec-decode still won
  (175 vs 161 tok/s decode, 64 vs 111 ms TTFT). At 4B the draft overhead
  eats the gain; decode-bound 30B+ residents are the only class where a
  spec-decode test can pay. The flag exists so a positive result is
  routable without a schema change.
- **prompt_cache (`cache_prompt`) — mlx_lm.server upstreams.**
  mlx_lm.server accepts `cache_prompt` for prefix KV reuse, and
  `mlx_lm.cache_prompt` can persist hot-prefix KV to disk. Agent harness
  prompts share long system prefixes — for those lanes, cache **affinity**
  beats load-spreading: the router pins a cache-holding lane to the
  resident that already holds its prefix instead of round-robining across
  specialists. TTFT is the metric that improves, not tok/s.
- **ttft_ms / tok_per_s per resident + TTFT-first scoring for interactive
  lanes.** The W115 method (same client, same prompt, medians) becomes a
  rolling per-resident measurement feeding belt's proven-latency scoring,
  split by lane class: interactive (claude sessions) scores TTFT-primary;
  batch (harvest, bench) scores throughput-primary. W115 shows why the
  split matters — a 64 ms vs 111 ms TTFT gap is invisible in a tok/s-only
  table.

Metadata shape: annotation fields on the inventory entry (remotes.json /
startup discovery / a buckle annotations file) — never invented, never
inferred from model names.

## 5. Micro-bench plan

Harness: `bench/router-bench.ts` in the buckle repo (pattern: belt's
bench-suite.ts plus W115's bun-fetch-and-SSE-parse client). Fully local: a
**mock upstream** (Bun.serve on a scratch port) simulates fixed TTFT, fixed
tok/s streaming, mid-stream death, 429 with and without retry-after, slow
drip. The router under test runs a policy pointing at the mock. Zero cloud,
zero model calls — the bench measures router cost, not inference. The same
harness pointed at real upstreams runs once in the shadow week for
end-to-end TTFT (§6).

Measurement: `T0` = handler entry, `T1` = first byte written to client,
`T_full` = last byte. added_latency = `T1 − T0` (streaming) /
`T_full − T0` (non-streaming). Percentiles over N ≥ 500 runs per scenario;
cold connects counted separately; sha256 byte-identity asserted per run.

| #   | Scenario                | Shape                                        | Targets                                                                                              |
| --- | ----------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 1   | Single stream           | 1 request, ~2 KB prompt, 256 tok @ 100 tok/s | p50 <5 ms, p95 <15 ms; byte-identity 100%                                                            |
| 2   | 50 concurrent           | 50 parallel streams, mixed sizes             | same gate; zero cross-stream contamination; router RSS delta <10 MB over the run                     |
| 3   | Failover mid-stream     | primary dies after first byte                | SSE `event: error` <50 ms after death; no re-route (would dupe content); tee stops; upstream aborted |
| 4   | Failover pre-first-byte | primary answers 502                          | fallback answer within +15 ms p95 (warm connect + headers only)                                      |
| 5   | Long stream + sniff     | 10-min stream                                | usage row within 1 s of the terminal chunk; sniff memory constant (tail window only)                 |
| 6   | 429 storm               | retry-after present vs absent                | header honored ± jitter; ladder walk <1 s; no request dropped while a rung is healthy                |
| 7   | Hot reload during load  | policy edit mid-run of scenario 2            | zero failed requests, zero dropped streams; new policy visible on the next request                   |
| 8   | Baseline cross-check    | same scenarios against LiteLLM on :4100      | record-only, no gate — one shadow run for the migration story                                        |

Gate: scenarios 1–4 carry the p50/p95 acceptance number; 5–7 are
ship/no-ship checks; 8 is context.

## 6. Could-not-verify

- Bun's idle-connection eviction timing — the 64-slot per-origin pool is
  documented via oven-sh/bun#42608, exact idle seconds are not pinned. The
  pre-warm/`pool_refill` heuristic covers it; shadow data will size it.
- HTTP/2 exact status boundaries in Bun 1.4.x (client experimental, server
  experimental behind `{http2: true}`) — flag-gated option, never a
  dependency; revisit at the shadow cut.
- Mock-to-real deltas: the bench measures router cost only; end-to-end
  numbers against real MLX/cloud upstreams come from the shadow week.
- Cloud 429 `retry-after` presence: unverified since W126/W131 — scenario 6
  covers both branches.
- Spec-decode benefit at 30B+: hypothesized from W115's negative result at
  4B, untested at 30B+. The metadata flag is the cheap bet; the test is a
  model-side lane, not buckle work.
